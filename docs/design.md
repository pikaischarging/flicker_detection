# 频闪检测工具 — 设计文档

版本 1.0 · 2026-08-01 · 对应 `requirements.md` v1.0

## 1. 设计概览

纯前端单页应用，两个运行时文件：`index.html`（结构 + 样式 + 标准说明文案）与 `flicker.js`（采集 + 分析 + 渲染）。无构建步骤、无运行时依赖、无后端。

### 1.1 核心设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| D-1 主分析判据 | 滚动快门条纹（空域） | 不受帧率 Nyquist 限制，可直接测 100/120Hz，是解决前一版不稳定的关键 |
| D-2 辅助判据 | 帧间亮度 FFT（时域） | 覆盖条纹判据的盲区：低频 PWM 调光 |
| D-3 曝光策略 | 尝试锁定 + 暴露状态 + 引导手动锁定 | 移动端多数不支持 manual，硬依赖会导致功能不可用 |
| D-4 相机约束 | 全部 `ideal` + 逐级降级 | 硬约束不被满足时 `getUserMedia` 直接抛错，而非退让 |
| D-5 结果定位 | 相对值 + 置信度 + 局限声明 | 手机测量无法校准，隐藏不确定性会误导用户 |
| D-6 存储 | 无 | 隐私优先，且需求不含历史记录 |
| D-7 测试策略 | Node + vm 沙箱注入 DOM 桩 | 无构建步骤下仍能测算法与渲染链路 |

## 2. 检测原理

### 2.1 滚动快门条纹（主判据）

CMOS 传感器逐行曝光，同一帧内不同行的曝光时刻不同。当光源亮度周期性变化时，时间轴被映射到图像的行方向，形成横向明暗条纹。

对一帧的逐行平均亮度曲线做 FFT，峰值幅度与直流分量之比即为调制深度：

```
调制深度 = 交流幅度 / 直流分量 × 100%
```

由于这条路径的采样率是"行率"（约为 帧率 × 行数），远高于帧率，因此不存在 100Hz 被混叠的问题。

**频率估算**：设一帧内有 `c` 个条纹周期、帧率 `f`，若近似认为传感器读出时间约等于一个帧周期，则

```
频闪频率 ≈ c × f
```

读出时间在不同机型上有偏差（通常 20% 以内），所以对落在 85~115Hz 的结果吸附到 100Hz、115~140Hz 吸附到 120Hz，对应 50/60Hz 市电的二倍频。超出范围则直接给原始估计值。

### 2.2 帧间亮度 FFT（辅助判据）

逐帧取画面中心 ROI（占画面 35%）的平均亮度，得到时间序列。受帧率限制，Nyquist 上限仅 15~30Hz，无法直接测 100Hz，但能发现驱动电源的低频 PWM 调光。

### 2.3 判据合成规则

```
若 条纹有效帧比例 > 30%：
    百分比 ← 条纹调制深度（中位数）
    频率   ← 条纹频率估计
    置信度 ← 有效帧比例 > 70% ? 高 : 中
否则：
    百分比 ← 时域调制深度
    频率   ← 时域峰值频率
    置信度 ← 低，标注混叠风险

若 时域调制 > 当前值 × 1.5 且 时域调制 > 10%：
    改取时域值（捕捉低频 PWM），
    同步更新频率与混叠标注，置信度从「高」降为「中」
```

最后一条的同步更新是刻意的：早期实现只改了数值不改元信息，导致界面出现"分析方式：帧间亮度 · 置信度：高"这种自相矛盾的输出。

## 3. 信号处理设计

### 3.1 处理链

两条路径共用同一套预处理：**去线性趋势 → Hann 窗 → 零填充至 2 的幂 → 基-2 FFT → 抛物线插值细化峰值**。

| 步骤 | 目的 | 实现 |
|------|------|------|
| 去趋势 | 消除画面上下方向的光照不均与残余渐变，同时去直流 | 最小二乘拟合直线后相减，`detrend()` |
| Hann 窗 | 抑制频谱泄漏 | `applyHann()` |
| 零填充 | 满足基-2 FFT 长度要求 | `nextPow2()` |
| FFT | 频域分解 | 原地基-2 Cooley-Tukey，`fft()` |
| 峰值插值 | 修正真实频率不落在整数 bin 上导致的幅度与频率低估 | 三点抛物线拟合，`refinePeak()` |

### 3.2 幅度标定

Hann 窗使幅度衰减一半，单边谱需 ×2，故

```
幅度 = 峰值模长 × 4 / M
```

其中 `M` 是**真实窗长**，不是零填充后的长度。这一点容易写错：条纹路径中行数 240 被填充到 256，若用 256 作分母会系统性低估约 6%。

### 3.3 重采样衰减补偿

时域路径的帧时间戳并非严格等间隔，需重采样到均匀网格才能做 FFT。线性插值等效于与三角核卷积，其频响为 `sinc²(f·Δ)`（`Δ` 为原始采样间隔），会衰减高频分量——例如 60fps 下的 10Hz 信号被衰减到 91%。

因此在细化出峰值频率后，按 `sinc²` 反向补偿幅度，补偿系数下限截断在 0.25 以避免接近 Nyquist 时放大噪声。实测该补偿把 15.6% 的真实调制从测得 14.07% 修正到 15.43%。

### 3.4 两种百分比估计的取舍

| 估计方法 | 优点 | 缺点 |
|---------|------|------|
| 峰峰值 `(max-min)/(max+min)` | 符合 IES 原始定义，对波形形状无假设 | 采样稀疏时采样相位很少落在波峰上，系统性低估 |
| FFT 基波幅度 / 直流 | 对采样相位不敏感，抗噪 | 对谐波丰富的非正弦波形低估 |

两者的失效场景不重叠，故取**较大值**作为输出。

### 3.5 帧有效性与鲁棒性

| 措施 | 设计 |
|------|------|
| 亮度门限 | 行均值 < 12 或 > 245 的帧判为不可信（暗处噪声大、过曝处调制被削平），返回 null 不计入 |
| 最低周期数 | 条纹分析跳过低于 1.5 周期/帧的频率成分，避免把光照渐变误判为条纹 |
| 离群值 | 多帧结果取**中位数**而非均值，避免个别晃动帧污染结果 |
| 无调制 | 完全无周期成分时返回深度 0（而非 null），使理想直流光源被正确判为优秀 |
| 有效帧比例 | `有效帧数 / 总帧数` 作为置信度依据 |

## 4. 模块结构

`flicker.js` 单文件，按职责分段。全局仅暴露 `CFG`、`state` 与函数（`index.html` 内联事件依赖 `startMeasure` / `showModal` / `hideModal` 三个全局函数）。

### 4.1 配置与状态

```js
CFG = {
  captureSeconds: 4,     // 采集时长
  warmupMs: 700,         // 预热丢弃时长
  roiRatio: 0.35,        // 中心 ROI 占比
  targetWidth: 320,      // 离屏 canvas 降采样尺寸
  targetHeight: 240,
  minBandCycles: 1.5,    // 条纹分析最低周期数
}

state = {
  stream, video, canvas, ctx,   // 采集资源
  running,                      // 采集中标志
  timeSamples: [{t, lum}],      // 时域样本
  bandSamples: [{depth, cyclesPerFrame, mean}],  // 每帧条纹结果
  frameCount, fps, watchdog,
}
```

### 4.2 函数职责

**相机层**

| 函数 | 职责 |
|------|------|
| `initCamera()` | 建离屏 canvas、逐级降级取流、调用曝光锁定、回填相机信息 |
| `tryLockExposure()` | 查 `getCapabilities`，尝试 manual 曝光/白平衡/对焦；不支持则静默返回 |
| `updateCameraInfo(settings)` | 渲染实际分辨率、帧率、曝光锁定状态 |

**采集层**

| 函数 | 职责 |
|------|------|
| `startMeasure()` | 复位结果、初始化相机、装看门狗、驱动帧回调循环、更新进度 |
| `captureFrame(tMs)` | 单帧处理：drawImage → getImageData → ROI 均值 + 逐行均值 → 两路样本 |
| `armWatchdog(ms)` | 兜底定时器，帧回调停止时强制收尾 |
| `resetButton()` | 按钮与进度条复位 |

**分析层**

| 函数 | 输入 | 输出 |
|------|------|------|
| `analyzeBanding(rowProfile)` | 一帧的逐行亮度 | `{depth, cyclesPerFrame, mean}` 或 `null` |
| `analyzeTemporal(samples)` | 时域样本序列 | 频谱、峰值频率、两种百分比、闪烁指数、有效帧率、Nyquist |
| `computeFlickerIndex(lums)` | 亮度序列 | 高于均值部分面积 / 总面积（0~1） |
| `summarizeBanding(samples)` | 全部条纹结果 | 中位深度、中位周期数、有效帧比例 |
| `estimateFrequency(cycles, fps)` | 周期数与帧率 | Hz，带 100/120Hz 吸附 |
| `finishMeasure()` | — | 合成判据并触发三个渲染函数 |

**渲染层**

| 函数 | 职责 |
|------|------|
| `renderResult(r)` | 星级、颜色、百分比、解释、频率、闪烁指数、判据、置信度、帧数 |
| `renderWaveform(lums)` | 时域波形 + 均值虚线 + 亮度范围标注 |
| `renderSpectrum(t)` | 频谱柱状图 + Nyquist 标注 + 峰值频率标注 |
| `setupCanvas(c)` | 按 `devicePixelRatio` 设置画布尺寸，避免高分屏模糊 |
| `showError/showHint/resetResults` | 消息与状态复位 |
| `showModal/hideModal/bindLongPress` | 标准说明弹窗与长按手势 |

**数学工具**：`nextPow2` `median` `detrend` `applyHann` `refinePeak` `fft` `sinc2`

### 5.3 标准说明弹窗

两个入口（FR-5.1 / FR-5.2）：「📋 标准说明」按钮，以及长按结果卡片 500ms。长按实现同时绑定 touch 与 mouse 事件，`touchmove` 取消（避免滑动误触），并阻止 `contextmenu` 防止系统菜单弹出。

## 6. 异常处理

| 场景 | 检测方式 | 处理 |
|------|---------|------|
| 浏览器不支持 `getUserMedia` | 启动时特性检测 | 显示错误并禁用按钮 |
| 取流失败 | 三级降级全部失败 | 显示 `错误名: 错误信息` + HTTPS/授权提示 |
| 曝光锁定不支持 | `getCapabilities` 无 manual | 静默降级，界面显示「曝光:自动」 |
| `getImageData` 抛错 | try/catch | 跳过该帧 |
| 帧回调停止 | 看门狗超时（采集时长 + 3s） | 样本 ≥ 16 则出结果，否则报错并复位 |
| 样本不足 | `analyzeTemporal` 返回 null | 提示「采集到的数据太少」 |
| 无有效条纹 | 有效帧比例 ≤ 30% | 退回时域判据，置信度置低，给出改善建议 |
| 页面卸载 | `beforeunload` | 停止所有 track 释放摄像头 |

## 9. 已知取舍与后续方向

**本版刻意未做**

| 项 | 原因 |
|----|------|
| 历史记录与对比模式 | 需求明确"目前无需存储数据" |
| SVM 指标 | 计算需要标准化的人眼时间响应模型，手机测量精度不足以支撑 |
| 曝光时间反解 | 需要机型标定数据，无法通用 |
| PWA 离线支持 | 增加 Service Worker 复杂度，收益有限 |

**可能的改进方向**

- 多次测量取中位数，进一步压低单次抖动
- 用行率而非帧周期近似读出时间，提高频率估算精度（需机型标定）
- 结果分享为图片，便于选购时对比
- 曝光时间已知时，按 `sinc` 反卷积补偿逐行曝光的低通效应
