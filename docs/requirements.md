# 频闪检测工具 — 需求文档

版本 1.0 · 2026-08-01

## 1. 背景与目标

办公室日光灯的频闪是否会造成视觉疲劳，是个日常但难以自证的问题。专业频闪仪价格高、不便携，普通人无法验证自己每天待 8 小时的光环境，也无法验证"护眼灯"的宣传是否名副其实。

手机的 CMOS 摄像头本身就是一个可用的光电传感器。本工具用纯前端方式把它变成一个能出数、能分级、能对比的频闪检测器。

**目标**：让非专业用户在 10 秒内知道"我头顶这盏灯的频闪算好还是算差"，并理解这个结论的依据和可信程度。

**非目标**：不追求实验室级绝对精度，不替代专业频闪仪，不做跨设备数值比较。

### 1.1 前一版本的问题

上一版基于帧间亮度分析，测量结果不稳定，反复测同一盏灯得到的数值差异很大。根因分析：

| 因素 | 影响程度 | 机理 |
|------|---------|------|
| 自动曝光 | 主因 | 相机持续补偿亮度变化，主动把频闪信号削平；补偿量随环境变化 |
| 分析方法 | 主因 | 手机帧率 30/60fps，Nyquist 上限仅 15/30Hz，测 100Hz 日光灯得到的是混叠值，随实际帧率漂移 |
| 距离与焦段 | 次要 | 通过改变进光量间接触发曝光调整，本身不直接影响调制深度 |
| iOS / Android 差异 | 次要 | 曝光策略与降噪算法不同，iOS 平滑更激进 |

本版本的设计以解决前两项为核心。

## 2. 用户与场景

**目标用户**：关心光环境的普通办公人群与家长，无光学或信号处理背景。

| 场景 | 描述 | 关键需求 |
|------|------|---------|
| S1 办公室体检 | 用户对着头顶日光灯测一次，想知道好坏 | 结论要直白，不能只给一个裸数字 |
| S2 灯具对比 | 同一台手机先测日光灯、再测护眼灯，对比谁更好 | 同设备下的相对可比性 |
| S3 选购验证 | 验证"AAA 级护眼灯"宣传 | 需要标准依据与常见光源参考值 |
| S4 外行理解 | 用户看到 12% 不知道意味着什么 | 需要可查阅的评级标准与解释 |

## 3. 功能需求

### FR-1 摄像头采集

| 编号 | 需求 | 优先级 |
|------|------|-------|
| FR-1.1 | 通过 `getUserMedia` 获取视频流，优先后置摄像头、优先高帧率 | 必须 |
| FR-1.2 | 相机约束必须全部为软约束（`ideal`），并在失败时逐级降级重试，禁止因单一约束不被满足而直接失败 | 必须 |
| FR-1.3 | 尝试锁定曝光、白平衡、对焦；不支持时静默降级，不阻断流程 | 必须 |
| FR-1.4 | 在界面显示实际分辨率、帧率、曝光是否锁定 | 必须 |
| FR-1.5 | 采集必须由用户手势触发（移动端策略要求） | 必须 |
| FR-1.6 | 页面提供实时预览与中心 ROI 指示 | 必须 |

### FR-2 采集流程

| 编号 | 需求 | 优先级 |
|------|------|-------|
| FR-2.1 | 单次采集时长约 4 秒 | 必须 |
| FR-2.2 | 丢弃开头约 0.7 秒数据，等待曝光稳定 | 必须 |
| FR-2.3 | 显示采集进度与当前阶段（曝光稳定中 / 采集中 x%） | 必须 |
| FR-2.4 | 优先使用真实帧时间戳采样，避免同一帧被重复采样 | 必须 |
| FR-2.5 | 帧回调停止触发时（页面切后台、锁屏、掉流）必须在有限时间内收尾，不得永久挂起 | 必须 |
| FR-2.6 | 采集结束后按钮恢复可用，允许重复测量 | 必须 |

### FR-3 分析

| 编号 | 需求 | 优先级 |
|------|------|-------|
| FR-3.1 | 主判据必须不受相机帧率 Nyquist 限制，能测 100/120Hz | 必须 |
| FR-3.2 | 辅助判据需能发现低频调光（PWM）问题 | 必须 |
| FR-3.3 | 输出频闪百分比（调制深度） | 必须 |
| FR-3.4 | 输出闪烁指数 | 应当 |

| FR-3.6 | 剔除过暗、过曝的不可信帧 | 必须 |
| FR-3.7 | 对个别晃动帧带来的离群值具备鲁棒性 | 必须 |
| FR-3.8 | 输出置信度，并保证置信度、判据来源、频率三者自洽 | 必须 |

## 4. 评级标准

依据 IEEE PAR 1789 与 GB/T 9473-2022，按频闪百分比分四档：

| 等级 | 频闪百分比 | 判定 | 说明 |
|------|-----------|------|------|
| ★★★ 优秀 | < 3.2% | 无危害 | 护眼灯级别，长时间读写无忧 |
| ★★☆ 良好 | 3.2% ~ 8% | 低风险 | 符合 IEEE PAR 1789 低风险线 |
| ★☆☆ 一般 | 8% ~ 25% | 合格 | 非最佳，光敏感人群可能疲劳 |
| ☆☆☆ 较差 | > 25% | 不建议 | 长期使用易视觉疲劳，建议更换 |

边界归属：取值落在边界上时归入较差的一档（如 3.2% 判为「良好」，8% 判为「一般」，25% 判为「较差」）。

**频闪百分比定义**

```
频闪百分比 = (最大亮度 - 最小亮度) / (最大亮度 + 最小亮度) × 100%
```

**常见光源参考值**（用于用户自校准预期）

| 光源类型 | 典型频闪百分比 |
|---------|--------------|
| 老式电感镇流器日光灯 | 50% ~ 100% |
| 电子镇流器日光灯 | 10% ~ 30% |
| 低端 LED 灯 | 20% ~ 80% |
| 中端 LED 灯 | 5% ~ 15% |
| 合格护眼灯 | < 3% |
| 直流供电 LED | ≈ 0% |

## 5. 非功能需求

| 编号 | 类别 | 需求 |
|------|------|------|
| NFR-1 | 部署 | 纯静态站点，可直接部署到 GitHub Pages 免费域名 |
| NFR-2 | 隐私 | 无后端、无数据上报、无持久化存储；视频帧仅在内存中处理 |
| NFR-3 | 依赖 | 运行时零第三方依赖，不引入 CDN 资源 |
| NFR-4 | 兼容 | 支持移动端 Chrome 与 Safari；桌面 Chrome 可用于调试 |
| NFR-5 | 性能 | 分析在采集期间实时完成，采集结束即出结果；不得因逐帧处理而丢帧 |
| NFR-6 | 可测试性 | 核心算法与渲染链路可在 Node 环境下无浏览器测试 |
| NFR-7 | 可维护性 | 单文件 HTML + 单文件 JS，不引入构建步骤 |
| NFR-8 | 诚实性 | 不得以确定语气呈现不确定结果；方法局限必须对用户可见 |

## 6. 约束与已知局限

| 编号 | 局限 | 应对 |
|------|------|------|
| C-1 | 摄像头 API 要求安全上下文（HTTPS 或 localhost） | Pages 默认 HTTPS；README 说明本地调试方式 |
| C-2 | 移动浏览器普遍不支持 `exposureMode: manual` | 尝试锁定 + 显示锁定状态 + 引导手动长按锁定 |
| C-3 | 测量结果是相对值，跨设备不可比 | 免责声明 + 说明文档中明示 |
| C-4 | 时域路径受帧率 Nyquist 限制，频率可能混叠 | 主判据改用不受此限制的方法；混叠时明确标注 |
| C-5 | 逐行曝光时间对高频信号有低通作用，深度可能偏低估 | 缩短曝光时间；结果定位为相对对比 |
| C-6 | 无滚动快门条纹的光源（如直流 LED）条纹判据失效 | 自动退回时域判据并下调置信度 |

## 7. 验收标准

| 编号 | 验收项 | 通过条件 |
|------|-------|---------|
| AC-1 | 算法精度 | 合成信号下，30% 调制测得误差 < 1 个百分点；2% 调制误差 < 0.15 个百分点 |
| AC-2 | 频率识别 | 合成 4 周期/帧条纹，识别误差 < 0.15 周期；100/120Hz 能正确归类 |
| AC-3 | 评级正确性 | 四档边界值归属符合第 4 节定义 |
| AC-4 | 场景区分 | 日光灯 / 护眼灯 / 电感镇流器 / PWM 四类合成场景评级结论正确 |
| AC-5 | 真实链路 | 真实浏览器 + 虚拟摄像头跑完整流程，无 JS 错误，结果与图表正常渲染 |
| AC-6 | 报告自洽 | 判据来源为时域时不得标注「置信度：高」，且必须提示混叠风险 |
| AC-7 | 异常兜底 | 帧回调停止时有限时间内收尾；样本不足时报错并复位按钮 |
| AC-8 | 相机兼容 | 设备不满足理想帧率时仍能成功取流（不抛 OverconstrainedError） |
| AC-9 | 标准可查 | 按钮与长按两种入口均可打开说明，含第 4 节全部内容 |
